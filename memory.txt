# DocMind — Long-Term Project Memory

## 1. Goal & Scope
- Project: DocMind — local RAG (Retrieval-Augmented Generation) web app using Flask, LangChain, local Hugging Face embeddings, Chroma, and Gemini API.
- Target user: Single local user. No deployment, no auth, no SQL DB, no frontend frameworks.
- Must NOT do: Hallucinate outside retrieved context, expose GEMINI_API_KEY, or add out-of-scope features (auth, SQL, Docker, deployment, streaming, agents/tools, OCR, Celery, automated tests, React/Angular).
- Privacy rule: Gemini Free Tier prompts and sent chunks may be used by Google to improve products — do NOT upload private/sensitive documents.

## 2. Tiered Features (all kept; build strictly in tier order)
- Tier 1 (Core): Upload PDF/TXT/MD (allowlist + size limit), parse & chunk, local HF embeddings, persistent Chroma with chunk metadata (doc_id, filename, page, chunk_index), grounded Q&A across all docs with "I couldn't find that in your documents" fallback, citations (filename, page, chunk preview), persistence across restarts.
- Tier 2 (Intermediate): Document library (list + chunk counts + full delete), per-session memory with standalone question rewriting, single-doc scope filter, per-document summary, relevance-score guard (skip Gemini below threshold), UI loading/clear/friendly error & 429 rate-limit handling.
- Tier 3 (Stretch — only if requested after Tiers 1–2): Settings panel (top-k, chunk size, temperature), Markdown chat export, duplicate content detection, /health route, local request logging.

## 6. Contracts & State Decisions
- JSON Response Wrapper (all routes): { "success": true|false, "data": <payload|null>, "message": "<string>" }
- Document ID: Generated UUID (doc_id) in documents.json and chunk metadata; original filename kept for display.
- Duplicate filename upload: Reject with HTTP 409 Conflict ("already exists; delete it first").
- Document deletion: Delete Chroma chunks by metadata filter (where={"doc_id": doc_id}), remove documents.json entry, delete raw file from data/uploads/.
- Conversation memory (Tier 2): In-memory Python dict keyed by session_id (resets on Flask restart; documents persist on disk).
- Multiple browser tabs (Tier 2): Independent per-tab session_id stored in browser sessionStorage.
